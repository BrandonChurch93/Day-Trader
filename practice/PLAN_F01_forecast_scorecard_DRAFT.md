## Part 2: Private no-future test

- INFERENCE, leakage gate: Default to a forward test. Pin an immutable model checkpoint and workflow; lock each forecast with a custodian before the deadline and before the answer is first knowable, not merely before formal resolution. Run stateless with browsing, retrieval, memory and tools off. Historical replay is allowed only if both earliest knowable outcome and resolution come after every model's documented information cutoff, including any model that prepares inputs; prove the exact pre-deadline question version and evidence. Prefer an offline checkpoint released before the question existed. An unknown cutoff, mutable alias, edited question, uncertain clock or possibly memorized benchmark disqualifies historical replay.
- INFERENCE, roster and custody: Prelist approved sources and categories; include all eligible binary cards in time order under fixed horizon and exclusion rules. Write an unambiguous Yes/No rule, deadline at least 24 hours before the first possible observed outcome, and authoritative source/vintage; keep overlapping events in the same block and exclude duplicates. Drop void/unresolvable cards by a frozen rule, count them and report all exclusions. Separate off-repo cards, hashed/timestamped forecasts and sealed outcome keys; preserve publication, deadline, earliest outcome and actual resolution as distinct UTC fields. No labels may influence prompts or row selection. No raw rows in the public repo.
- MEASURED, inputs: The current web-search tool has no enforceable per-question cutoff. A search date hint or an old publication date on a current page does not prove what was visible. INFERENCE: First run is model-only, on frozen question text and criteria. A separately registered context arm may use only rights-cleared documents with exact versions and publication times proved to precede the deadline.
- INFERENCE, baselines: Use 50% and a fixed category rate \((Y+1)/(n+2)\) based on disjoint data with labels known before freeze; below 20 category examples use the pooled rate, then 50% if none. Optional community baseline is the last rights-cleared timestamped crowd value in the hour ending at the fixed forecast checkpoint, hidden from the model. No snapshot or permission means no comparison; no current value or later fill-in ([API specification](https://github.com/Metaculus/metaculus/blob/main/docs/openapi.yml)).
- INFERENCE, scoring: Mean Brier \((p-y)^2\) and natural-log loss \(-[y\ln p+(1-y)\ln(1-p)]\), lower is better; clip probabilities to \([.01,.99]\) uniformly for log loss only. A missing/invalid prediction scores as 50%; report coverage. Primary paired gain is category Brier minus model Brier. On matching crowd rows, report community minus model log loss in nats; this is not the official peer score against individual forecasts ([Metaculus scoring FAQ](https://www.metaculus.com/help/scores-faq/#tournament-scores)).
- INFERENCE, sample: For 80% power and two-sided 5% significance, \(\lceil[(1.96+.84)s/.02]^2\rceil\) gives 385 independent-equivalent resolved cards at paired gain SD \(s=.14\) (\(384.16\) before rounding) and 636 at \(s=.18\) (\(635.04\)). These are assumptions for detecting a .02 Brier gain against zero, not findings. With a 1.5 variance multiplier for correlation and 10% unresolved, plan for \(636(1.5)/.90=1{,}060\) scheduled cards. Use a disjoint 30-card variance/clock/cost pilot, not an edge claim. Freeze sample, event/time blocks and calendar stop before scoring; too few effective resolved cards means inconclusive.
- INFERENCE, pass candidates: A: at least .02 mean paired gain, 95% paired block interval lower bound above zero, better Brier than 50%, no worse log loss than category rate, at least 95% valid predictions, and no leakage or custody failure. B: same, but lower bound above .02 to claim the gain exceeds .02; power against a true .04 gain or recalculate. Lead locks one before intake; no stopping on a win.
- INFERENCE, cost and next step: One call per card; no calls for baselines or scoring. Allow one identical transport retry only before the deadline, so 30 pilot calls normally, 60 max. At 2,000 input and 300 output tokens, per-card cost is \(.002R_{\rm in}+.0003R_{\rm out}\) at dollars per million tokens, plus billed reasoning/retries. Exact dollars UNKNOWN until the model and rates are fixed. Register the ledger, cost cap and independent terms/clock review first. A pass justifies asking the owner about a bot account for a live season, not forecasting prize money, proving a trading edge, or entering.
