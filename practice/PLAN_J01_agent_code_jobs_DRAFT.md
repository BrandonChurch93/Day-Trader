# J01 draft: can an agent do a funded code job without help?

INFERENCE: Test whether one agent can produce both a credible proposal soon enough to matter and a private, merge-quality fix without a human guiding it. Start with Expensify as a practice source only. Its rules allow AI assistance but require human ownership and review; an honest AI label alone does not make unattended submissions permissible. This is Queue 146 / Doc 205 row 6. Draft only: no job attempted, candidate repo downloaded, account made, proposal written for posting, payment made, or contact with a maintainer.

## Private attempt and scoring

- INFERENCE, freeze and isolate: A custodian saves issue title and body as visible at the cutoff, timestamp, label and assignment events, public job metadata, language, and the exact observed default-branch commit SHA. Hash the manifest and the issue and repo inputs. Save original evidence outside the solver sandbox. The solver receives only sanitized issue title/body and code at that SHA, including repo-local docs and tests, with no comments of any vintage, no Git history, remotes, issue URLs, later commits, proposals, outside tools, network, credentials, or human hints. Exclude issue text that quotes competing fixes or already contains an implementation; record why. Never reconstruct past issue prose from a later edited body. Prefer prospective snapshots to reduce memorization; no guarantee the fixed model never saw preexisting public examples.
- INFERENCE, fixed run: One agent arm, one frozen model ID and version, fixed decoding/settings and exact prompt hashed before draw. Proposed prompt: “Using only the issue and the supplied source tree, produce a concrete fix proposal first, then implement the smallest correct patch, run relevant checks, and list verified results and open risks. Do not infer results you did not test.” First checkpoint at 10 elapsed minutes and at most 10 model calls; archive the first submitted private draft with its actual timestamp; if not sealed by the checkpoint, fail the proposal score. Do not let the solver replace it. Total at most 60 elapsed minutes and 45 calls including retries, one try per job, no fallback model. Count every model invocation, all elapsed minutes including setup/build, and report attempt, judge and preparation separately. Use a sealed local environment and synthetic fixtures only. Preparation uses pinned dependencies, no unreviewed network scripts or secrets. A build failure, unavailable fixture or timeout after admission stays in the denominator and cannot be swapped.
- INFERENCE, fixed primary judgment A+C: Before a solver sees the job, a separate agent reads only its title/body and frozen code, builds and seals a hidden reproduction that fails on the baseline for the stated reason, and seals the regression command set. An independent reviewer agent then receives the patch and frozen materials, not real proposals, accepted fixes, run time or solver identity. Score PASS only if the patch passes the hidden reproduction, introduces no failures against baseline in the locked repo tests/lint/types, and the reviewer says merge with written reasons on scope, correctness, maintainability and test evidence. Missing reproducible baseline, hidden test, verdict or patch is not a pass; tally infra failures separately. Independently score whether the sealed 10-minute proposal describes the problem, likely cause, concrete fix, and how to verify it; unsupported claims fail. Nobody feeds feedback back to the solver.
- INFERENCE, secondary judgment B: After all outcomes are locked, a separate reader tracks later accepted/merged fixes for up to 30 days; compare observable behavior and run accepted regression tests against base and private patch when portable without importing the fix. Different code can be correct; a later test may depend on unrelated changes. No accepted fix, no test or nonportable test is UNKNOWN, not a failure or a rescue of primary score. A+C is fixable before the run; B is delayed corroboration and has selection bias. None proves the maintainer would accept ours, the proposal was original relative to other entrants, or we would be first.
- INFERENCE, race clock: For each drawn ID record UTC issue creation, when both Help Wanted and the stated dollar offer first became visible, when we drew it, the first public proposal by anyone (tag MelvinBot separately), the first eligible non-sponsor proposal, first proposal that meets the same credibility rubric (secondary), first review assignment and first actual implementation authorization/assignment, with event links and timestamps. Compute post-to-proposal, offer-to-eligible-proposal, offer-to-implementation-assignment, capture lag, and whether draw time plus locked proposal time beat the first eligible proposal and implementation assignment. Include pre-label proposals in the raw clock but not the eligible clock; an existing real proposal means the “beat first” comparison is a loss, not an exclusion. No event yet is right-censored; deleted, edited or ambiguous evidence stays UNKNOWN; don't set missing times to zero. This is a conservative race proxy, not claimant selection or earned payment.
- MEASURED, race spot checks only: On [#107116's event log](https://api.github.com/repos/Expensify/App/issues/107116/timeline?per_page=100), Help Wanted appeared at 14:37:17 UTC and the first visible proposal-formatted comment at 14:37:52 UTC, a 35-second gap. [#106630's event log](https://api.github.com/repos/Expensify/App/issues/106630/timeline?per_page=100) shows one second from label to a proposal-formatted comment; neither comment's timestamp proves quality or eligibility. INFERENCE: A daily draw and 10-minute checkpoint are likely too slow to beat the first timestamp. Keep that loss visible; measure time to credible proposal and actual assignment separately instead of changing the gate after seeing scores.

## Proposed marks and money interpretation

- INFERENCE, pick before running: Target 12 distinct issues; fewer is feasibility only. Recommended gate: at least 8 of 12 primary fix passes, with at least 4 of 12 joint passes (good fix and credible proposal before the first eligible outside proposal and actual assignment) on at least two distinct weeks with known race clocks. Stricter alternative: 10 of 12 fixes and 6 of 12 joint passes. Unknown time cannot count toward a joint pass. These are feasibility thresholds, not statistical proof of repeat monthly revenue. Record issue price, clock, failure class, model calls and elapsed minutes for every drawn ID, as well as median and max cost for completed and failed attempts. The lead fixes one gate, cost cap, cutoff and stop rule before seeing jobs.
- INFERENCE, arithmetic and decision: Monthly gross scenario = qualifying offers per 30 days × observed joint-pass fraction × assumed real assignment fraction among joint passes × assumed deployment/payment fraction among assignments × posted gross price. For scale only, the nine visible recent label rows are not verified eligible flow. If all nine were eligible monthly at $250, a 4/12 joint pass mark yields $750/month at impossible-to-assume 100% real assignment and settlement, or $187.50/month at an assumed 25% combined conversion. For a prospective run of D calendar days, calculate qualifying flow as 30 × unique qualifying offers / D and use cohort posted prices, not a single top price. Real qualifying flow, fees, conversion and cash arrival are UNKNOWN today; budget $0. One-job limit and deployment exposure can lower even that scenario. Do not annualize a point-in-time backlog.
- INFERENCE, what a pass buys: It warrants asking the owner to open an account and consider a separately authorized, disclosed submission pilot only if the payer expressly allows that agent role and the owner can meet its human-review duties. A pass never authorizes posting, unattended account access, or autonomous submission, and cannot prove hiring, production deployment, payment, profitability, or reliable autonomous income. A fail or underfilled sample means no account recommendation on this evidence.
