# TM09 operator handoff (ledger 222, queue 115)

This is build machinery, not authority to launch, fetch market data, score, or inspect results. Use the dedicated non-root service account `tm09desk`, private `/var/lib/tm09` (0700), and a root-owned, read-only, pinned TM09 release in a separate directory, for example under `/opt/tm09-releases/`. Use worker scratch `rig/tm09_scratch/<sid>` and briefs under `rig/tm09_briefs`, with exact hashes pinned and only the opaque worker session ID in paths. Do not use TM07 paths, tape, service user, ports or credentials. Schedule setup separately from live TM07 sessions. Allow only ports 8801–8806, check availability at each launch, and choose the port and arm launch order independently of arm identity. Every `launch` takes its port explicitly and binds loopback only.

## Prepare and sign

1. Place recorded `stock_sessions.jsonl`, `stock_bars.jsonl` and `stock_news.jsonl` in a service-owned 0700 direct child directory of `/var/lib/tm09`; pass its absolute path as `--export-dir` and bind it as `export_dir` in approval. Keep no workspace copy. Use ordinary non-symlink files, private to custody and the service, not the worker. Minute bars: `symbol,tf,t,o,h,l,c,v`, `tf=1Min`; `t` is the UTC minute-open epoch second. Use the full 38-name roster, regular-session minutes, exact venue close minute, and sufficient preceding recorded session-calendar coverage to avoid attributing an older item to the first study wake. News clocks and metadata follow `tools/tm09_stock_news_counts.py`; do not run that script for author review. `stock_universe.jsonl` is supporting custody evidence, not input for dropping names. Never follow the TM07 tape symlink. Share export hashes and row counts only.

Custodian creates canonical signed capsules via `tm09_desk.seal(key, domain, body)` as `{"body": body, "seal": signature}` only after the lead authorizes that specific scope. A signature authenticates the custodian's attestation; it does not attest to provider behavior automatically. Store approvals and evidence privately. Use absolute direct paths, a pinned release, and invoke modules from that release as the dedicated service, not as the worker or root.
3. Each capsule body binds `root`, `service_uid`, absolute `release`, `approved_by`, `release_files` (SHA-256 map for the modules, tests and brief listed in `tm09_operator.approved`), `config_sha256`, and `registration_sha256`. The standard-library parser accepts only the pinned single-line flow values and the TM09 value block. Build scope `ledger-222-build-fixtures` also binds `export_dir` and `export_sha256`, a map keyed by exactly the three input basenames. Run `python3 -m timemachine.tm09_operator build --root ROOT --key-file KEY --approval BUILD_CAPSULE --export-dir EXPORT`. Output is one private no-headline fixture per week, canonical fixture digests in `fixture-pins.json`, and a counts-only tally of skipped edited or changed-clock rows. Do not print data or the fixtures.
4. Rehearsal scope `ledger-222-rehearse-tm09` binds the same release, `resolved_settings` (exact output of `tm09_fixture.settings` before adding limits), `limits` (`notes`, `note_chars`, `looks`, `look_rows`, `headline_rows`, `headline_chars`), an operator's `operator_boundary_sha256` attestation and explicit `ports`. 5. Run scope `ledger-222-run-tm09` additionally binds `export_dir`, `export_sha256`, `fixture_pins`, and `synthetic_rehearsal_sha256`. Sign only after review of the rehearsal, no-web/no-outside-tool enforcement, private-feed delivery, provider no-training/no-raw-logging controls and worker boundary evidence. Input beyond signed bounds is refused rather than silently truncated. The signed ports must be a subset of the enforced pool.

## Create, serve and review

Use `python3 -m timemachine.tm09_operator COMMAND --root ROOT --key-file KEY --approval CAPSULE --week YYYY-MM-DD --role ROLE`. For a boss add `--boss MODEL --arm ARM` privately, with the arm labels from settings. Only the service-private manifest and slot map contain labels; never put operator arguments or private paths in worker scratch, jobs, briefs or logs. `create` returns only an opaque ID. For `launch`, add `--port PORT --boundary START_CAPSULE` and pass `--export-dir` for the production news scout. Confirm the exact ready line before briefing: `Registered desk ready; brief only this session's roles.` Give the worker only its own bearer, opaque SID and endpoint plus the pinned brief and, for a successor, verified same-session handoff. End every worker before reuse of its sandbox, bearer transport, or port. The service signs notes once, after scout completion. `export-notes` saves only the immutable wake-indexed notes to `scout-export.json`; create the two scouts first, then the bosses. The service reads the pinned headline export at the news scout endpoint only; do not turn on transport or model request/response dumps.

If a worker is lost, stop it and run `successor` once on the same slot. Provide the replacement bearer and the signed same-session handoff; old bearer and wake key no longer work. Keep completed session state intact. Never restart a completed worker or create a replacement slot to repeat its run. A refusal, dependency failure or missing bar is not evidence of a completed outcome.

The operator verifies a current unique nonce in the privilege-audit canary log before each `launch`, checking that the earlier prefix is unchanged and the unique canary line is present in the added tail. Put only redacted evidence (`session`, `port`, `nonce`, `matched_canary: true`, `prefix_unchanged: true`, `size_before`, `size_after`) in `--canary-proof`. Sign `ledger-222-tm09-launch` with `session`, `port`, `nonce` (32 lowercase hex characters), `canary_observed: true`, `sudo_size_before`, `sudo_size_after`, and `sudo_checkpoint_sha256` (hash of the exact proof bytes). No build or worker process runs sudo or reads the privilege-audit log. The service-only key and signed, matching receipt and proof are required before binding. Launch creates nonce-bound signed control and stop JSON recording a bounded journal range. Supervise graceful stop; a missing stop receipt is a review failure, not a pass.

Run `python3 -m timemachine.tm09_isolation_probe` from the actual sandboxed worker against the active invented rehearsal desk and with `--stopped` after service stop; for closed real sessions run the post-stop variant only, with no replay content requested. Use `--port`, `--session`, `--sibling`, `--bearer-file`, and repeated `--canary` with direct paths to existing TM09-only canaries for private tape, notes, key and results. They must exist and deny reads, not merely be absent. The operator inspects the worker process scope, no-egress controls and the privilege-audit tail against the approved allowlist, then signs `ledger-222-tm09-review` with `session`, `port`, `nonce`, `control_sha256` (canonical capsule fingerprint), `post_stop_probe_sha256` (exact proof-file bytes), `sudo_review_sha256`, and true `sudo_allowlist_reviewed`, `raw_copies_denied`, `listener_stopped` flags. Run `review --boundary END_CAPSULE --probe-proof PROOF` with usual slot arguments. It verifies the stop, control and probe evidence and saves only redacted route outcomes: method, allowlisted path (or `unknown`), opaque session ID and status. Every route attempt is separately journaled. Review the worker command allowlist outside the service; its listener is not an OS sandbox or proof of hosting policies.

The runner stores decisions, accepted-note text, fill and completion receipts. It does not store raw news payloads. The news-note filter rejects a complete current or previously seen headline even if case and punctuation change; it cannot prove that all notes are sound paraphrases. Require isolated operator/provider controls and a privacy review policy before real feed delivery, without exporting quotations or using the other arms' prompt context.

## Close and score

Profit figures are not worker routes. At window close and only on separate lead approval, use scope `ledger-222-seal-results` with `window_closed: true` and the same run evidence, then run the operator `results` command without week/role/arm arguments. It writes private `sealed-results.json` with every scheduled week, completion/null statuses, and delivery counts; stdout contains no return. Keep analyst access closed until the score ceremony.

Run `python3 -m timemachine.score_tm09 --root ROOT --approval SCORE_CAPSULE --key-file KEY --registration REG --config CONFIG --sealed-results SEALED` only with lead approval. Score capsule domain `tm09-score-approval`; body fields `scope: ledger-222-score-once`, selected Stage 2 `mode`, `root`, `approved_by`, `release`, `scorer_sha256`, `dependency_sha256` (basenames and file digests listed in `score_tm09.DEPS`), `config_sha256`, `registration_sha256`, `results_path`, `results_sha256`. It refuses before opening the result path unless approved. It compares registered marks using exact rational arithmetic. Benchmark data gaps are sealed per week with a reason. They do not remove a primary/placebo week, change the benchmark roster, or block the handoff; they withhold the forward label if they affect any included comparison week. The exclusive score claim remains on any failure; stop and reconcile with the lead, do not delete it to retry. Net values are separate from finish and access journal records; finish contains status only. Keep `scored.json` private and arrange the independent blind recomputation from the same seal before reporting.

## Rulings and limitations

TM04 allowed fractional positions; the later TM09 registration supersedes that for bosses. Only the benchmark is fractional. Orders are long-only whole-share target vectors. The first one-minute bar that starts strictly after the wake is used (10:00 wake, 10:01 open if recorded), subject to the next wake and session close. Share-volume caps apply first; same-minute buys that exceed remaining cash are scaled pro rata and rounded down. No sizing mark or no eligible bar means an unfilled cancellation with no carry. `sparse-counts` reports counts per symbol and recorded market session without prices, quantities or returns. Decision acknowledgment never depends on later data; settlement appears at the next wake, and the terminal mark is resolved only by the operator results command. A missing exact terminal mark stays unavailable without substitute pricing. The stored wording's original historical vintage and Alpaca hosted-model clearance remain the registration's open questions.
