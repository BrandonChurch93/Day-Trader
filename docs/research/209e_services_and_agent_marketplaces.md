# Paid services and agent marketplaces: from order to bank

INFERENCE: Test a fixed-scope file cleanup sale and the same tool billed per successful run on Apify, privately and with fake money. AWS gives a buyer's agent a direct path to USD billing, but has a heavier seller setup. No route cleared acquiring customers, delivery, exceptions and reliable bank income together. UNKNOWN: Median net income and time to first bank dollar for a newcomer under these designs.

MEASURED means an opened primary page shows the rule or observation; STATED means someone claims an outcome, not an audited result; INFERENCE means our judgment or proposed design; UNKNOWN means not established. Rule check: November 27, 2026. INFERENCE: These are paper designs. No account, posting, purchase, contact, wallet action or keyed call was part of the study.

3. SCAFFOLDING: INFERENCE: Tie checkout to an order ID and accept only a verified final successful payment event, not a redirect or duplicate notice. MEASURED: Stripe documents completed checkout events and additional events for delayed payment methods ([Stripe fulfillment](https://docs.stripe.com/payment-links/post-payment)).
4. AGENT ALONE: INFERENCE: Explain known mappings and abstain on ambiguous input. SCAFFOLDING: Apply a deterministic transform and compare counts/invariants before private delivery with a short-lived download; block cross-customer access and unapproved model uploads.
5. SCAFFOLDING: INFERENCE: Send routine receipt, status and delivery. AGENT ALONE: Answer allowlisted questions and make no new commitments; escalate rights, scope, or quality complaints.

OWNER EVERY TIME: Decide contested refunds, chargebacks and discretionary concessions as they arise. 7. OWNER ONCE: INFERENCE: Set bank payout schedule. SCAFFOLDING: Reconcile verified bank deposits against processor entries, refund and fee totals. OWNER EVERY TIME: Handle identity, reserve or other holds if they occur. - UNKNOWN, evidence: Verified volume, newcomer median net, first order and time to first bank dollar. - INFERENCE, verdict: WORTH A TEST, not a launch recommendation.

3. SCAFFOLDING: INFERENCE: Use platform buyer billing and start a run, with limits and idempotent event accounting. MEASURED: Apify also describes prepaid buyer-agent tokens for qualifying Actors with limited permissions ([Apify monetization](https://docs.apify.com/platform/actors/publishing/monetize)).
4. SCAFFOLDING: INFERENCE: Deliver validated output and bill exactly the documented result event, not failed work. AGENT ALONE: Explain known exceptions without false assurances.

## Ranking for private work only

- **Direct CSV cleanup**: INFERENCE, WORTH A TEST first. Build a fake order ledger and try to break it. It gives the most control over ordinary delivery and refunds but supplies no customers.
- **Apify Actor**: INFERENCE, WORTH A TEST second if the same core passes. Add mock usage billing and month-end netting. Its store supplies distribution, not proven conversion.
- **No third test**: INFERENCE, keep AWS and transparent agent marketplaces on WATCH. None justifies spending, opening an account, posting an order or calling it reliable unattended income. Reopen a real pilot only with separate approval, authorized buyers and delivery, an observable customer path, manageable exception load and actual bank reconciliation.
