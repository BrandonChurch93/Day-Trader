# AI Agent Integration Across 12 US Brokers and Crypto Venues

Date: 2026-11-24
User context: US retail individual in Nampa, Idaho, trading US stocks, ETFs, and spot crypto.
Architecture context: In our target design, deterministic rule-based code places orders, while AI builds, researches, and reviews. This report ranks all 12 firms for that design first, then separately evaluates direct AI agent trading (MCP servers and agentic accounts) for readers who want it.

Confidence tags used throughout:
- `MEASURED`: Verified directly on the firm's or provider's own page today (2026-11-24).
- `STATED`: Reported by a third-party source or marketing summary when no primary page confirmed the specific detail.
- `UNKNOWN`: Could not be verified from available public pages today.

## Executive Summary and Ranked Table (Rule-Based Execution + AI Coding Agent)

For a system where an AI coding agent builds and tests code while an unattended rule-based service places live orders, five factors separate strong venues from weak ones:
1. A real paper or sandbox environment so the AI coding agent can test order logic without risking money.
2. Machine-readable docs (`llms.txt`, OpenAPI specs) and an actively maintained official Python SDK.
3. Server-side client order ID deduplication so network retries do not double-fill.
4. Safe unattended credentials (scoped keys with withdrawals disabled, IP allowlists, isolated sub-accounts or portfolios, and no forced human re-login).
5. Clear permission in the firm's terms for personal automated trading.

### Top Picks by Asset Class
- Best for US stocks and ETFs: **Alpaca** (#1). It is the only US equities broker that combines an actively maintained official Python SDK, published OpenAPI spec, `llms.txt`, full free paper trading, server-side `client_order_id` deduplication, WebSocket streaming, and permanent API keys for unattended operation.
- Best for spot crypto: **Kraken** (#2) and **Coinbase** (#3). Kraken wins on paper testing against live prices (`kraken-cli`) plus granular key permissions and IP allowlists, while Coinbase wins on official Python SDK support plus portfolio-level key isolation (limiting a bot's blast radius to one funded portfolio). **Gemini** (#4) is a close third with a full pre-funded exchange sandbox and clean RBAC roles, though it lacks a finished official Python SDK.
- Worst for unattended rule-based bots: **Charles Schwab** (#11, 7-day forced browser re-login and no paper API) and **Robinhood** (#12, no retail equities REST API at all). **Interactive Brokers** (#9) has deep markets and paper trading, but individual retail accounts cannot use Web API OAuth and must rely on a local gateway with manual 2FA and daily session teardown.

## AI Model Provider Policies on Trading and Financial Advice

Our design (AI builds, researches, and reviews; deterministic code executes orders under fixed rules) aligns cleanly with all three major model providers' policies. By contrast, letting an LLM autonomously decide and execute live trades without human review directly conflicts with OpenAI's and Perplexity's policies and triggers Anthropic's high-risk controls if offered as personalized financial advice.

### 1. Anthropic Usage Policy
- Source: [Anthropic Usage Policy](https://www.anthropic.com/legal/aup) (`MEASURED`, Effective November 12, 2026).
- High-risk finance classification: Treats "Finance" as a High-risk Area defined as "a personalized recommendation to buy, sell, hold, or allocate among specific investment products, such as securities, funds, digital assets, or annuities..." (`MEASURED`).
- High-risk requirements: Delivering a "High-risk AI Recommendation" requires a qualified human-in-the-loop review and AI disclosure (`MEASURED`).
- Explicit safe harbors matching our design: Anthropic explicitly places two activities outside high-risk requirements:
  - "Internal drafting, research, summarization, or analysis that is not the ultimate High-risk AI Recommendation delivered." (`MEASURED`)
  - "Carrying out a decision a person has already made, or applying a fixed rule, formula, or algorithm where the model exercises no judgment about the individual." (`MEASURED`)
- Agents rule: "Agentic use cases must comply with the Usage Policy. Users are responsible for ensuring that agents they build or deploy, including actions those agents take through tools, browsers, or connected systems, comply with this Usage Policy." (`MEASURED`)

### 2. OpenAI Usage Policies and ChatGPT Agent Policy
- Sources: [OpenAI Usage Policies](https://openai.com/policies/usage-policies) (`MEASURED`, Effective November 20, 2026; changelog updated October 21, 2026) and [Using ChatGPT agent in line with our policies](https://openai.com/policies/using-chatgpt-agent-in-line-with-our-policies/) (`MEASURED`, Updated July 17, 2025).
- Licensed advice rule: Prohibits "building or offering AI tools that provide others with tailored advice that requires a license, without appropriate involvement by a licensed professional." (`MEASURED`)
- Automated high-stakes financial actions: Prohibits "automation of high-stakes actions in sensitive areas without human review. This includes actions, decisions, transactions, submissions, and other steps that materially affect a person's rights, safety, access to essential services, or other consequential interests in areas such as: ... financial activities and credit" (`MEASURED`).
- Explicit trading restriction for ChatGPT Agent: Users must not "Automate actions like stock trading or other investment transactions" (`MEASURED`).

### 3. Perplexity Acceptable Use Policy
- Source: [Perplexity Acceptable Use Policy](https://www.perplexity.ai/hub/legal/aup) (`MEASURED`, Effective January 1, 2027).
- Scope: Explicitly covers both Outputs and "tasks the Services may perform on your behalf ('Agentic Actions')" (`MEASURED`).
- Licensed financial services rule: Prohibits using the services for "medical, financial, tax, legal or other services that would typically require specialized credentials or licensing without appropriate professional oversight;" (`MEASURED`).
- Automated financial decisions rule: Prohibits using the service to "Make high-risk or consequential automated decisions or use Outputs to make high-risk or consequential decisions about individuals that materially impact them without human oversight. High-risk or consequential decisions include those regarding ... finances or credit..." (`MEASURED`).

Toolsets can be restricted with `ALPACA_TOOLSETS`, but all toolsets are enabled by default and there are no built-in order caps or read-only switches (`MEASURED`).
- **Developer Experience**: Official Python SDK [`alpaca-py` v0.45.0](https://pypi.org/project/alpaca-py/0.45.0/) released Nov 5, 2026 (`MEASURED`). Official OpenAPI specs ([Trading API OpenAPI JSON](https://docs.alpaca.markets/us/v1.1/openapi/trading-api.json), [SDKs and Tools](https://docs.alpaca.markets/us/docs/sdks-and-tools)) (`MEASURED`). Machine-readable [`llms.txt`](https://docs.alpaca.markets/us/llms.txt) (`MEASURED`). Free paper trading environment (`MEASURED`). WebSocket streaming for market data and trade updates (`MEASURED`). Server-side `client_order_id` idempotency up to 128 characters; duplicate IDs are rejected with HTTP 409 ([Alpaca CLI Docs](https://docs.alpaca.markets/us/docs/alpacas-cli)) (`MEASURED`).
- **Key Safety & Unattended Operation**: Retail Trading API uses permanent `APCA-API-KEY-ID` and `APCA-API-SECRET-KEY` headers, allowing unattended services to run without human re-login (`MEASURED`). Retail Trading API has no cash withdrawal endpoint, and crypto withdrawals require a 24-hour whitelisted address (`MEASURED`). OAuth2 Connect supports `account:write`, `trading`, and `data` scopes ([OAuth2 Docs](https://docs.alpaca.markets/us/v1.1/docs/using-oauth2-and-trading-api)) (`MEASURED`).
- **Terms on Automated / AI Trading**: The [Alpaca Customer Agreement](https://files.alpaca.markets/disclosures/library/AcctAppMarginAndCustAgmt.pdf) states accounts are self-directed and the customer is solely responsible for all orders; it does not prohibit personal automated trading, while prohibiting granting trading authority to another person without approved authorization (`MEASURED`).
