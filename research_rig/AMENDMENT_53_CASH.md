# Plan 53 cash amendment

Status FROZEN.

This document specifies the proposed replacement freeze, not an approval to validate or score. Its parent is the original Plan 53 freeze `21578de60e336702d9c764579768fc155110f770`. Only the lead can activate this replacement with the existing sole-file approval directly atop the new freeze. No real price, return, or vendor proof result informed the authoring of this amendment.

## Reason

STATED: The one-pass primary collection left most fund-years unresolved due to missing exact ex-dates or inaccessible sources. Giving those funds zero unverified cash while giving PCEF its documented cash can make a failed benchmark comparison hard to interpret. It can also change the roster comparison if primary coverage differs by fund family. UNKNOWN: The size of either effect on actual marks.

## Rules

- Keep tier 1 unchanged: the issuer, issuer wire, SEC and exchange evidence, including known events on partial rows. Use only tier 1 for PCEF. Neither the licensed vendor nor this amendment changes split handling, ranking, the roster, dates, costs, the seven marks or the Replay 48 engine.
- Validate the complete vendor input before deciding the gate. On roster fund-years marked `documented` or `none`, match vendor events to primary events one-to-one on exact ex-date and inclusive absolute amount tolerance. Sort by date and amount; on equal vendor date and amount, sort by currency state (blank first). A record cannot be reused. Every unmatched vendor event is extra, including all events in a `none` window. Windows with incomplete vendor queries are not clean. Clean means complete with no extra event, not necessarily no missed primary event.
- Use all primary events in those rows as the match denominator and all those rows as the clean-window denominator. Both must be nonzero. Both minimums in `config/thresholds.yaml` must be met with no rounding. Every native currency state among tier-2 candidates must appear on at least one matched proof event. An extra does not become a match by rounding, summing, splitting or rescaling the amount.
- Interpret native blank vendor currency as US dollars. Every roster member is a US-listed registered closed-end fund that declares in dollars; proof events also test amounts against primary USD amounts. Blank can mean USD, not applicable or unknown in the vendor documentation, so note that agreement is not independent currency verification. The only other permitted native state is explicit `USD`; refuse non-blank non-USD rather than converting it. Do not fill in blanks at collection.
- If the gate passes, admit `vendor_crosschecked` cash only from complete queries for `unresolved` and `partial` roster rows. On a partial row, primary wins on every date it already documents. Never replace a primary event or infer documented absence from an empty vendor result. If the gate fails, use tier 1 only. A malformed, missing, or unpinned proof input refuses the packet rather than masquerading as a failed gate.
- The scored marks use admitted cash and the same cash-zeroed leg for the loser-effect mark. After the lock, show primary-only and cash-zeroed tables as diagnostics, not extra decisions. Cash-zeroed removes all cash, including PCEF's, but keeps splits and costs. Show gate totals and diagnostic counts by turn and primary status after the lock; no cutoffs on those subgroups or changes after scoring. Pre-lock validation prints only counts, including the gate flag, without a return or mark.

## Packet and custody

The approval text and command-line pins are unchanged. The existing off-repo `manifest.json` mode is now `plan53_raw_sip_v2` and its file map adds the SHA-256 of `vendor_cash.json`. The primary `distributions.json` and `cash_coverage.csv` remain separate and unchanged. The scorer derives the effective tier-2 holding events from the same file it checks for proof, so there is no separate effective holdings file to prepare, edit, or approve. Raw vendor pages, historical symbol or security identity mapping, query scope and query/pagination receipts remain in owner-only off-repo custody for audit. Do not put raw amounts, evidence, price data, or comparison results in Git.

- `vendor_cash.json`: an owner-only file with top-level keys `schema` (integer version 1) and `turns` (object keyed by exact turn-year strings). Each turn maps every frozen roster ticker, and no other ticker, to an object with `complete` (boolean) and `events` (array). No PCEF row. Complete means the right historical instrument and event scope were verified and the window query finished, including all pages. For incomplete jobs set `complete` false and leave the array empty, retaining evidence separately. A complete query may return an empty array.
- Each event has `id` (stable nonempty vendor ID, unique within the fund-year), `ex_date` (ISO date), `amount` (positive exact JSON number per common share), `currency` (empty string or `USD`, preserving vendor state) and `source` (HTTPS audit reference with no credentials, userinfo, query or fragment). Retain actual cash events, including specials, not noncash actions, pay dates, canceled records or pagination repeats. Do not collapse distinct same-day actions. Use contemporaneous per-share amounts without split or currency conversion. Include only sessions after entry through the judged exit inclusive, ordered by ex-date then ID.

## Limits

The funds with complete primary records are not a random sample. They can differ from the missing funds in issuer, year, payout schedule, special payments and ticker or merger history. A pooled pass does not show that the vendor is equally accurate in those missing rows. It also cannot resolve a vendor total that mixes a known partial payment and a different payment on the same date; excluding all vendor cash for that date can leave the latter uncredited. Where the vendor has no usable cash, the original missing-cash imbalance can persist. Treat the shown counts and cash versions as checks on interpretation, not as permission to change the rule or rerun.
