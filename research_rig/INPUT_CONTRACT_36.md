## Custody and naming

Stage at the fixed platform path `/home/user/workspace/rig/data/plan36_inputs`; put external provenance/native download copies outside that directory. The fixed output path is `/home/user/workspace/rig/data/replay_36` and must exist before `--go`, but is not used in validation. Input and output directories must be private (`0700`); members are regular files owned by the scorer user, without group or other permissions, hard links or symlinks. No credential in any artifact. No candidate ticker, security price, per-share payout, or filing payload in the Git tree. Retain a missing/blocked full detail list in the private roster, and deliver only counts, SHA-256 digests and refusal codes outside the private run directory.

- **`manifest.json`**: JSON object, exact keys `schema=1, plan=36, vendor="Alpaca", feed="sip", adjustment="raw", frequency="1Day", filed_from="2016-01-01", filed_through="2026-09-30", bar_from="2016-01-04", bar_through, collected_utc, files`. `bar_through` is an actual pinned NYSE session no later than 2026-10-30; dates are inclusive, UTC timestamps are RFC 3339 with trailing `Z`. `files` maps exactly the five private payload names below to 64 lowercase hexadecimal SHA-256 digests. Use compact UTF-8 JSON, no BOM, NaN/Infinity, duplicate keys or blank JSONL lines.
- **`roster.jsonl`**: One line per chronological, issuer/class cooldown trigger in the point-in-time census, whether or not it can be traded. Schema: `id, cik, class_key, ticker, batch_date, buys, disposition, security, cap, routine, provenance`. `cik` and buyer CIKs are digit strings without leading zeros; `security` is the independent, stable identity of the traded common line (see `identities.jsonl`), not the reused ticker. Use `null` for unresolvable attributes. `id` is `batch_date:cik:class_key`; canonical order by that tuple. Optional early archive coverage starts in December 2015 only for cooldown/freshness warm-up; do not score those rows. Preserve accession, class and candidate ticker on all rejected rows. `provenance` is the SHA-256 of a private event evidence dossier; it contains source URLs, retrieval times and content hashes for purchase venue, role and originals; as-of correction review; explicit exclusion or unknown reason; and SEC quarterly coverage reconciliation including the last-day spillover. Only the freely posted 2026 Q3 cutoff is in scope. Quantify any missing late-September items deferred by the bulk release and do not infer their transactions.
- **`buys`**: Two or more descriptive entries when available; exact fields `accession, owner_cik, officer, director, trade_date, accepted_utc, public_utc, shares, reported_price, venue, plan`. Use ISO dates, UTC, positive finite decimal JSON numbers, boolean role flags, distinct original Form 4 accession/owner key pairs and code P/direct/Table I/common verified in the dossier. `public_utc` is the later of acceptance and documented dissemination when available, otherwise acceptance. Allowed `venue` values: `open_market, private, unknown`; plan: `no_indication, affirmative, historical_unknown, unknown`. Unknown clocks are `null`. Set `disposition` to `confirmed, venue_excluded, venue_unknown, plan_excluded, correction_excluded, clock_unknown, identity_unknown`. A `confirmed` or `identity_unknown` record must have a valid distinct-owner qualifying pair, one newly public on the batch date and no purchase from information public after the batch. Preserve all candidate ledger IDs, the reason for filtering and chronological recomputation of first cluster after filtering; reconcile removals/retriggers in the dossier. `routine` is `opportunistic, routine, mixed, unclassified`, shown only. `cap` is null or `{shares, asof, accepted_utc, source}`, using only data available before entry, from a latest eligible SEC-stamped single-common-line disclosure within 180 calendar days, already on the prior close’s share basis. Include share basis reconciliation in the dossier. Do not match on a present-day snapshot or forward fill future shares.
- **`identities.jsonl`**: Exact fields `security, symbol, from, through, source` for each non-overlapping date interval. One security can rename; one ticker may be reused, but not on overlapping intervals by different securities. Include stable IDs `IWM`, `IJH`, `IVV` only when their benchmark is actually needed. Secondary legs of actions use a linked dated interval. URLs or SEC filing links in `source`; supporting CIK/class/vendor-as-of proof and fetch hashes stay in provenance. Date-label matching and Alpaca `asof` are both mandatory; an empty response stays missing rather than triggering an unverified symbol search.
- **`bars.jsonl`**: Raw Alpaca historical daily SIP bars, one row per `security, date`; exact keys `security, symbol, date, t, o, h, l, c, v`. `t` is the original daily UTC stamp and must map to the pinned New York session date; use JSON numbers, no prices made up for missing days; `v` is reported share volume. Keep exact source request parameters, dates, identity handling and all pages in the custodian's provenance. An unavailable bar is an absent row, never a zero-price row. Do not send bars for unconfirmed events or arbitrary dates.
- **`quotes.jsonl`**: Historical SIP quote observations from Alpaca, for the exact requested security-date intervals only; exact keys `security, date, t, bid, ask, bid_size, ask_size`. `t` is original UTC quote timestamp with up to nine fractional digits; native bid/ask sizes must be independently converted to number of shares, with the rule and feed unit documented. Sort by security, date, timestamp, preserving source sequence within tied timestamps; the final state at that instant governs. Include all quote updates, including zero, locked and crossed states; these terminate the previous quote and do not count as valid duration. The quote window spans five minutes ending one minute before that session's scheduled NY close; include the prior 60 seconds for carry-in and the cutoff timestamp. Keep raw observations, not only computed averages. ETF closes are gross benchmarks; no ETF quote requirement or fee in the marks. ETF quotes, if provided, are limited to matched primary/delayed entry and scheduled exit dates.
- **`actions.json`**: Exactly `{coverage:[...], actions:[...]}`. Coverage rows: `{security,from,through,status,source}` with `status` exactly `complete` or `unresolved`, and official or vendor-backed plus independently checked provenance for every staged holding span, even when there is no action. Action rows: `{id,security,date,kind,amount,target,source}`. Dates are effective sessions (ex-date for distributions), in cash USD per held share or named share ratio per held share before that row's action. Allowed kinds and `amount`: `split` positive ratio, `cash` nonnegative per-share distribution, `stock_distribution` positive ratio to the required `target` security (can be the same security), `settle_cash` nonnegative cash per share including documented worthless removal, `settle_stock` positive successor ratio and required `target`. A cash-and-stock merger is represented by a `cash` plus `settle_stock` on the same effective date. Plain cash, split and settle cash have null target. Only one split and one settlement row per security/date; within a date process split first, then cash and stock distributions, then settlement. Require the source to normalize same-day amounts to the post-split basis. Cash/stock settlement only when documented value becomes realizable: a stock successor is valued at its verified raw close that session, never a made-up quote; missing exit closes/distribution basis go to unresolved. Secondary stock-distribution positions remain held to sale or documented earlier settlement and are not cash at issue. Document delayed payment, missing effective date, nonstandard rights/due bills and valuation uncertainties rather than inferring an amount. Missing actions are not zero.

## Smallest request procedure

1. The custodian rebuilds and reconciles the roster, all known corrections, late-quarter evidence and point-in-time mapping **before** market collection. Keep confirmed candidate IDs and code labels for everything else. Do not download the general live asset universe, all symbol history, October filings, current prices or adjusted prices.
2. For only confirmed, mapped issuer/class events, compute the exact union of adjacent XNYS runs: latest 20 completed sessions through prior to intended entry (bounded below by January 4, 2016), intended entry through intended exit (20 session intervals), and at most one additional session for the delayed diagnostic. Dilate only for individually evidenced action companion legs; use only their needed acquisition-to-exit window. Request each union run with the correct historical identity; trim responses to those dates. Do not add other tickers or fill missing history by interpolation. Record the last authorized bar held; a scheduled exit beyond it is an incomplete candidate even if shortened data exist.
3. From prior-session closes and already-known disclosure shares, determine which one of IWM, IJH and IVV is the approved size fund for each confirmed candidate. Request only the union of matching dates for the selected funds (intended entry through scheduled exit, one extra day for the shown-only delay using the same fund). Request near-close SIP quotes only for the security/date of each still eligible entry (plus scheduled exit when collected, the one-session-delayed window and verified companion exits); never request an intraday tape for all dates. Net entry needs valid stock quotes. Use no substitute feed. Preserve explicit no-SIP-quote/no-bar outcomes and vendors' response proof.
4. Pin the approved frozen code/calendar/contract separately from the real manifest, the reviewed source roster and the reviewed action packet. The approval commit binds the manifest and actions SHA-256 explicitly; the roster SHA-256 is inside the pinned manifest. `--validate-inputs` does not create a lock, quote a numeric price, or evaluate any return. The lead agent alone invokes `--go` after approval, validation and audit.
